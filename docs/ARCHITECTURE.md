# Architecture

`historia_core` depends only on JsonCpp and SQLite, never Drogon or inference. Typed `WorldState`, `TurnOrders` (free-text actions with optional targets), `ResolvedEvent` and `CountryContext` are in `simulation.h`; world deltas, operation compilation and feasibility rules are in `world.h`; national status, naming and monthly war consequences are in `status.h`. `DecisionProvider` and `NarrationProvider` are independent interfaces. `LocalProvider` implements both, accepting an injectable transport for tests, and requires a valid, reachable-looking (`http://127.0.0.1:<port>`) endpoint at construction — there is no scripted/offline mode.

The server validates a request, claims a persisted job under a mutex, snapshots the world and cached references, then queues work. HTTP event-loop threads do not run simulation or blocking inference. One bounded worker queue serializes turns and narration; a separate bounded worker handles reference preparation and refreshes. Automatic preparation deduplicates up to eight outstanding identities and backs failed requests off for an hour. A provider mutex enforces one inference request at a time; a separate settings mutex guards the endpoint value so it can be changed at runtime (`setEndpoint`/`endpointValue`) without waiting for an in-flight request. A turn asks the model for the actions of at most four AI nations, sequentially: nations the player's actions name or target, then open conflict parties and parties to small (at most three-member) commitments, then one rotating neighbor. Transport uses a dedicated event loop so shutdown does not cancel timeout dispatch. SQLite access is guarded separately; slow network work never holds the store mutex. A process-level file lock prevents two servers from owning the same save. The reference database opens read-only.

The active model endpoint is resolved at startup with precedence: an explicit `--llama-endpoint=` CLI flag, then the value persisted in that save's `settings` table, then the hardcoded default `http://127.0.0.1:8081`. A CLI flag, when given, also overwrites the persisted value. `POST /api/v1/model-config` updates the live provider and the persisted value together at runtime, so a web-UI change takes effect immediately and survives a later restart with no flag.

Actions are free text: 1–500 bytes each, at most eight per player and three per AI nation, with up to four existing region/entity/actor targets. `resolve` only advances the month and completes construction whose `completes_turn` has arrived; it performs no inference. The model then adjudicates all actions together, and `compileOperations` turns its answer into a validated `WorldDelta`, enforcing reach and pacing against the start-of-month world. `applyMonthlyStatus` then derives population, GDP, stability and war tolls deterministically from the state, the delta and region adjacency. The model contributes only qualitative inputs (effects, a war's kind and intensity), never numbers. Replay applies `resolve`, the recorded deltas and `applyMonthlyStatus`, independent of model repeatability.

Player requests carry campaign UUID, expected turn and idempotency key. Duplicate keys return the original job only if the entire request matches. A new key for a stale turn or a running campaign is rejected. Full validation precedes job creation. Model output is parsed strictly, rejects extra fields, and passes the same identifier, schema, duplicate and length checks; any decision that fails these checks, or that the model failed to produce at all (unreachable, timed out, malformed), fails the whole turn with no state change — there is no fallback decision. Narration receives authoritative events only and has no mutating interface.

A transaction writes the resulting state, all intentions, events, frozen reference documents, factual summary and completed job status. Initial campaign state is saved separately for replay verification. Any failure rolls back all those changes. Optional narration replaces only its own row after commit, and its own failure independently falls back to the already-committed factual summary (this is the one fallback that remains — it reports literal event text, not a model-authored decision). On restart, pre-commit running jobs become interrupted; their world did not advance. Resubmission uses a new key. Completed jobs remain completed even if narration was interrupted. New-game replacement clears the active campaign/journal/jobs atomically, retaining the reference cache. Job IDs are not reused.

Contexts contain the actor's regions (compactly), occupations, entities, open conflicts and commitments, recent and related historical events. Cached reference is explicitly separated and clipped. Every request is measured against the context size the server reports: a byte estimate when it is well inside, otherwise the server's tokenizer, trimming optional references and history first. Cached material cannot authorize outcomes. JSON schema is defense in depth; only C++ validation authorizes world changes.

Reference refresh uses fixed Wikimedia hosts, 12-second request timeouts, code validation and country-level ISO property P297. France, Norway, Kosovo and Taiwan use explicit entity overrides. English article titles come from entity sitelinks, never city IDs. Missing/ambiguous entities stay unavailable. Current references are not historically date constrained. The full document used by a turn is persisted before future refreshes can affect it.

Chronicles replace the raw history excerpt for nations. Before a month's decisions, the turn worker asks the model (no thinking, kind `chronicle`) to write a history of at most 250 words for the player and for reactive AI nations in an open conflict or an open commitment of at most three parties with the player, at most three per month. Nations merely named by the player and independent national slots get no new chronicle; they use an earlier one or the excerpt. A chronicle is written when missing, at least 12 months old, or written without a source when the nation's `history_source` is now cached. A first chronicle, or a source-less one being rebuilt, condenses the cached `history_source` with all the nation's campaign events; later ones rewrite the previous chronicle with the nation's campaign events since, so the campaign's history builds up. Agreements and wars carry a start date (`since`, e.g. "March 2026") rather than a month count, so chronicles name years. Chronicles are saved outside the turn transaction as a cache, so a failed turn keeps them. A failed chronicle call never fails the turn: the nation keeps its earlier chronicle or the excerpt. Chronicles are untrusted reference material like excerpts, and the turn record freezes the chronicle each prompt used. Regional actors keep their excerpts.

## Extension points

- Deeper warfare: army strength, supply or casualties can extend the entity model and the reach rules in `compileOperations`; keep them start-of-month and deterministic so replay stays exact.
- Historical scenarios: add versioned scenario datasets and explicit January-2026 source cutoffs; do not relabel current fictional stats as history.
- Enhanced models: implement the provider interfaces and retain strict local validation and hard failure on any invalid or missing result.
- Reaction caching: key by provider/version, scenario, actor, full relevant state and frozen reference revision; cache actions, not mutations.
- Training traces: export validated contexts, proposed/accepted intentions, rejection reasons and authoritative events from replay records; add consent and dataset licensing before training.
- Scale: separate reference/narration queues from turn resolution and add explicit cancellation, token accounting and a schema migration policy. Turns and reference work already use separate queues.

No authentication or remote serving is provided. Host/origin checks and JSON-only mutation requests protect the local API from accidental cross-origin use. Do not expose the port publicly.


## Independent politics and identity persistence

`politics.cpp` schedules slots using a stable FNV-1a hash with an avalanche finalizer of campaign ID, month and actor/region ID. National slots are distinct and exclude the player. Regional selection ranks governing nations before their eligible regions, excluding residual geometry and invalid control. Cooldown and reactive overlap are preferences, relaxed by scarcity. SQLite `monthly_allocations` freezes the first allocation across retries; successful turns save allocation, intentions, input contexts and source snapshots. Independent decision contexts omit current player orders. Trusted initiative attribution is copied by the provider from intentions onto their corresponding outcomes; missing/misaligned outcomes fail the turn.

Regional state is a separate `regional` delta collection keyed by territory ID. Regional decision requests omit national military inventory and include their own history, agenda, authority and reference. The compiler restricts regional operations to `regional_initiative`, while `respond_regional` checks current national control and an existing pending demand. Every selected regional attempt appends bounded history, including unsuccessful outcomes. Authority derives from current control, never a stale stored sovereign ID.

`change_identity` preserves actor IDs and unrelated identity fields. New-state creation and substantive rename/refounding operations store specification, deterministic SVG, renderer version and originating event in actor identity revisions, in the same state transaction. C++ accepts only hex colors, four layouts and circle/diamond/no emblem; arbitrary markup never reaches SVG. Invalid or repeated designs use a seeded geometric fallback. Previous revisions are immutable. Minor spelling corrections keep flags. The campaign/actor/revision endpoint prevents stale browser flags; journal links retain event-time revisions.

Backward compatibility is additive: absent political collections decode empty, existing static flags remain, and legacy fictional actors use a deterministic endpoint fallback. Replay compares decoded canonical worlds so old exports lacking the new collections still verify. Reference identities stay separate from campaign identities; renamed real actors retain their original real reference identity, while fictional actors have none.

Regional outcomes have a required, territory-specific agenda operation in the inference schema, and C++ checks that requirement again. Verified regional reference matching requires a unique exact English label plus P17 country and direct P131 national parent; unmatched or lower-level names remain unavailable.
